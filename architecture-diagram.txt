2) COMPONENTS & DATA FLOW  (the source of truth)
================================================================================

LAYER A — USER
  • Browser (Analyst/Architect) — opens the dashboard, explores the globe,
    cost explorer, security posture, etc.

LAYER B — HOSTING & IDENTITY  (Azure App Service – one Linux Web App)
  • App Service serves BOTH the built SPA (static files) AND the Express API
    from a single origin / single port.
  • Managed Identity — the app's cloud identity used for read-only Azure calls.
  • Microsoft Entra ID (Easy Auth) — gates who can open the app.
  (Locally this same code runs under your `az login` session instead of an MI.)

LAYER C — FRONTEND  (Vite + TypeScript SPA, no UI framework)
  • deck.gl 3D globe / world map — Map, Heatmap, Arc and Path layers.
  • Lenses + live panels — Overview, Cost, Trends, Waste, Posture, Ops, Risk, WAF.
  • Cost Explorer — group-by, daily-stacked, accumulated, custom ranges, drill-down.
  • Forecast, anomaly detection, Pareto/concentration, inventory, tag governance.
  • Typed API client — calls the backend with relative `/api/...` URLs.
  • Exports — Excel, PDF, CSV.

LAYER D — BACKEND  (Node.js + Express, server/index.mjs)
  • REST `/api/*` endpoints (context, summary, regions, inventory, cost,
    optimize, posture, resource detail, service-health, …).
  • Caching — in-memory TTL cache + disk cache (`.cache/`) to survive throttling;
    OPTIONAL Azure SQL database for long, throttle-proof cost history.
  • Auth — DefaultAzureCredential: Managed Identity in Azure, Azure CLI locally.
  • Subscription discovery — Azure CLI locally; ARM Subscriptions API in the cloud.

LAYER E — AZURE DATA PLANE  (all READ-ONLY)
  • Cost Management ........ spend, trends, forecast inputs
  • Resource Graph ......... inventory, regions, linkage/dependencies
  • Defender for Cloud ..... security assessments / posture
  • Azure Advisor .......... cost/reliability/security recommendations
  • Azure Monitor .......... resource metrics
  • Service Health ......... incidents & advisories
  • ARM Subscriptions API .. subscription enumeration (cloud)

DATA FLOW (numbered)
  1. Analyst opens the app → HTTPS → App Service → Entra Easy Auth → SPA is served.
  2. SPA makes relative `/api` calls → Express API (same origin, same port).
  3. Express requests a token from Microsoft Entra ID via its Managed Identity
     (DefaultAzureCredential).
  4. Express runs READ-ONLY queries against the Azure data plane
     (Cost Management, Resource Graph, Defender, Advisor, Monitor, Service Health).
  5. Results are cached (memory + disk, optional Azure SQL) to avoid rate limits.
  6. JSON flows back to the SPA, which renders the 3D globe and the live panels.

KEY PROPERTIES
  • Read-only — never creates, updates, or deletes Azure resources.
  • No stored secrets — auth is delegated to Managed Identity / Azure CLI.
  • Single origin — one Web App hosts UI + API (easy to deploy and secure).

    (headers), grey #E1DFDD (borders), green #107C10 (the read-only badge).
